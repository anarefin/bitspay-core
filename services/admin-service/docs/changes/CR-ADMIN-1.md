## 1. Motivation
SRS v1.2 (14 Oct 2026) adds the release `MVP` before R1 with six features, including bill payment against an internal biller catalogue (BIL-011, UC-16) and mobile recharge (BIL-012, UC-17), both with a simulated provider (A-41). admin-service owns the product switches (ADM-005, C-01), so `FEATURE.BILL_PAY` and `FEATURE.RECHARGE` must be seeded enabled and every product outside the MVP disabled. Payers need receipts for the two new transaction types (NOT-002, NOT-003). Open decisions B-24 (pilot audience) and B-25 (catalogue sign-off) apply.

## 2. Change (before → after)
- **Data contract `refdata-system-params` — `FEATURE.<PRODUCT>` seed.** Before: enabled `P2P, CASH_IN, CASH_OUT, MERCHANT_PAYMENT, MERCHANT_REFUND, FLOAT_TRANSFER, REVERSAL`; disabled `DISBURSEMENT, SCHEDULED_TRANSFER, REQUEST_MONEY, CAMPAIGN, ADD_MONEY, WALLET_TO_BANK, BILL_PAY, RECHARGE, REMITTANCE, CARD, OFF_US_QR`. After: enabled `P2P, CASH_IN, CASH_OUT, MERCHANT_PAYMENT, MERCHANT_REFUND, FLOAT_TRANSFER, REVERSAL, BILL_PAY, RECHARGE`; disabled `DISBURSEMENT, SCHEDULED_TRANSFER, REQUEST_MONEY, CAMPAIGN, ADD_MONEY, WALLET_TO_BANK, REMITTANCE, CARD, OFF_US_QR` (BR-GOV-47). Item shape unchanged.
- **`codes.yaml` → `notificationTemplates`, new group-A templates (additive).**
  - `BILL_PAYMENT_SUCCESS`: TRANSACTIONAL, FROM_WALLET, IN_APP + SMS. Variables `amountPoisha`, `feePoisha?`, `billerName`, `billReference`, `providerReceipt?`, `txnRef`, `time`.
  - `BILL_PAYMENT_FAILED`: IN_APP. Variables `amountPoisha`, `billReference?`, `failureCode`, `txnRef`, `time`.
  - `RECHARGE_SUCCESS`: IN_APP + SMS. Variables `amountPoisha`, `feePoisha?`, `msisdn`, `operatorName?`, `providerReceipt?`, `txnRef`, `time`.
  - `RECHARGE_FAILED`: IN_APP. Variables `amountPoisha`, `msisdn?`, `failureCode`, `txnRef`, `time`.
- **`TXN_FAILED` trigger text:** + `txnType nin [BILL_PAY, RECHARGE]` (the template itself is unchanged).
- **Seed rules (internal):**
  - New: R-BILLPAY-CUST, R-RECHARGE-CUST, R-BILLPAY-FAILED, R-RECHARGE-FAILED.
  - R-TXN-FAILED is narrowed so the payer gets one failure message.
  - No message to the biller wallet (BR-NOT-16).
- **Reminder policy `BILL_DUE`:** unchanged, stays disabled (R1+).
- **GL export removal:** admin's SPEC and rules had no `GL_EXPORT_READY` / `GL_EXPORT_FAILED` routing; those codes appear only in `contracts/consumed/general-ledger-service/codes.yaml`, which was not edited here (the orchestrator re-pins). Removed one reference in SPEC §5.3 (approval routes): `GlExport` from the list of general-ledger entity types (11 → 10).
- **SPEC:**
  - Header and §1.2 / §1.3 updated for MVP vs R1+.
  - §2: baseline SRS v1.2, "· MVP" markers, new rows BIL-011, BIL-012, UC-16/17.
  - §5.3 / §5.4 mirrors, §6.3 consumed mirror (`BILL_PAY`, `RECHARGE`, `billReference`, `msisdn`, `providerReceipt`).
  - New BRs BR-GOV-47 and BR-NOT-16; §7.8 seed texts; §7.12 rules.
  - §10: WPs tagged [MVP]/[R1+], plus WP-CR-1.
  - §11 tests, §13 (B-24, B-25, MVP deferrals), §14 changelog, Appendix A.
