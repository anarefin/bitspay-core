## 1. Motivation
The MVP release (SRS v1.2) has no customer self-onboarding journey, because OTP, PIN and the e-KYC provider are R1. MVP customers are created by **assisted onboarding**: a back-office staff member creates the customer (ONB-002, `assistedBy` from `X-Actor-*`), captures the documents and decides basic KYC.

The decision (MVP decisions, 2026-10-14): **onboarding uses no maker-checker in the MVP**. One staff member decides, in one step, and the audit trail records who did it. ONB-018 and BR-W-25 (maker proposal → `OPS_CHECKER`, level 2 for HIGH/PEP) return in R1 through a configuration switch.

Seeded customers are allowed only in the `local`, `dev`, `qa` and `demo` profiles, never in `prod`. That is an internal rule with no contract change.

## 2. Change (before → after)
**Behaviour (SPEC BR-W-25, ONB-011, ONB-018)**: new config `bitspay.wallet.kyc.decision-mode`, with values `SINGLE_STEP` (MVP default) and `MAKER_CHECKER` (R1).
- **Before:** `POST /v1/kyc-submissions/{submissionId}:decide` by `OPS_MAKER` → submission `PENDING_APPROVAL` + approval request `APPROVE_KYC` / `REJECT_KYC`. The `OPS_CHECKER` approves (level 2 `COMPLIANCE_OFFICER` / `CAMLCO` for HIGH or PEP), and only then are the tier and wallet status applied.
- **After (`SINGLE_STEP`):**
  - `:decide` by `OPS_MAKER` applies the decision in the same transaction: on APPROVE the tier is set, the risk grade stored, the wallet goes `P → A` and `KYC_APPROVED` is emitted; on REJECT the result is `KYC_REJECTED`. No approval request is created.
  - HIGH grade or PEP still requires the EDD fields `sourceOfWealth` and `eddNote`, but needs no second level.
  - The compliance screening gate (BR-W-23) is unchanged: `:decide` APPROVE still needs `SCREENING_COMPLETED CLEAR` (or a cleared case).
  - `AUDIT_RECORDED` `KYC_DECIDED` carries the deciding user, the grade and `decisionMode`.
  - The `prod` profile may run `SINGLE_STEP` only while `bitspay.release = MVP`.
- Response of `:decide`: `KycSubmission.status` is now `APPROVED` / `REJECTED` instead of `PENDING_APPROVAL` (`SINGLE_STEP` only). It is the same schema, but the meaning changes, which was first classified as kind C.
- The operation summary and description change from "Maker proposal …" to "Decide APPROVE / REJECT (single step in the MVP; maker-checker in R1, BR-W-25)".

```json
// POST /v1/kyc-submissions/{id}:decide  {"decision":"APPROVE","targetTier":2}
// before → {"submissionId":"…","status":"PENDING_APPROVAL","approvalId":"…"}
// after  → {"submissionId":"…","status":"APPROVED","approvalId":null}
```

**Unchanged:** profile-update maker-checker (ONB-023), partner approval chains, and the compliance SCREENING / EDD case four-eyes decisions (compliance-service).
